# L1 性能模型

用 Python 估算整个大模型在 FPGA 上推理时的运算量、数据量和耗时。模型里的周期公式和运算清单都经过 RTL 仿真与 L0 实际执行的校验，只有板卡带宽、PCIe 延迟等外部参数是假设值。

代码在 `l1/perf.py`，完整输出在 `l1/report.md`。

## 可信度：哪些是验证过的

| 部分 | 来源 | 校验 |
|---|---|---|
| 运算清单（每 token 各运算的元素数、MAC 数） | 按 L0 运算流统计 | 与 L0 实际执行逐项相等（单元测试） |
| 矩阵单元周期 | 公式 `nt × (5 + kb×32) + 46` | 与 RTL 实测完全相等（stories15M 每 token 483,564） |
| 向量单元周期 | 每单元的载入 / 计算 / 输出拍数 | 与 RTL 实测完全相等（6 种运算） |
| 板卡带宽、PCIe 延迟、驱动开销 | 公开规格粗估（2026-11-16） | **未验证**，上板后用实测替换 |

> **已按可综合版 RTL 更新（2026-11-16）**：矩阵单元公式改为 `nt × (5 + kb×32) + 46`（双组累加器，不再每 tile 停 32 拍），向量单元公式见 [RTL 可综合与时序](07-RTL-可综合与时序.md)。第一版 RTL 的公式保留为 `V1`，两版的实测值都写在单元测试里。下文数字均为当前版。

## stories15M 每 token 的运算量

| 项目 | T=1 | T=256（满长度） |
|---|---|---|
| 权重矩阵乘 | 1519 万 MAC | 1519 万 MAC |
| 注意力（q·K、P·V） | 3,456 MAC | 88 万 MAC |
| 非线性运算（元素 × 遍数） | 约 5 万 | 约 8.6 万 |
| 读权重 | 15.39 MB | 15.39 MB |
| 读 KV Cache | 3.5 KB | 903 KB |

结论：**权重矩阵乘占绝对多数**；注意力和 KV Cache 随上下文长度线性增长，长上下文时才变得重要。权重 + 满长度 KV Cache 共 25.65 MB。

## 四种架构的每 token 耗时（stories15M，KU040 板，T=128）

| 部分 | A0-MMIO | A0-DMA | A1-RTL | A1 |
|---|---|---|---|---|
| 矩阵乘（FPGA） | 1.93 ms | 1.93 ms | 1.93 ms | 1.93 ms |
| 非线性 + 注意力（电脑） | 0.51 ms | 0.51 ms | — | — |
| 非线性 + 注意力（FPGA） | — | — | 0.41 ms | 0.13 ms |
| PCIe 往返 | 0.94 ms | 0.75 ms | 0.01 ms | 0.01 ms |
| **合计** | 3.38 ms | 3.19 ms | 2.36 ms | 2.07 ms |
| **token/s** | 296 | 314 | 424 | 483 |

- **A0-MMIO**：只有矩阵乘在 FPGA，x 逐字写寄存器（即 L2 第一版的接口）
- **A0-DMA**：同上，x / y 改用 DMA + 中断
- **A1-RTL**：整个模型在 FPGA，按当前 RTL（向量单元每周期 1 元素）
- **A1**：整个模型在 FPGA，向量单元 16 路、注意力走矩阵单元

结论：只把矩阵乘放 FPGA 时，**PCIe 往返占 1/4 以上时间**；整模型搬上 FPGA 后，PCIe 每 token 只剩一条命令，几乎可以忽略。

| Llama-3.2-1B | 1.27 GB | ✗ | ✗ | 6.1 / 10.7 | 7.3 / 130 |

| 板卡 | 时钟 | 存储带宽 | 容量 | PCIe |
|---|---|---|---|---|
| A7-200T（Artix-7） | 150 MHz | DDR3 32 位 4.5 GB/s | 1 GB | Gen2 x4 |

## 关键结论

1. **解码速度 ≈ 存储带宽 ÷ 权重字节数**。每生成一个 token 都要把全部权重读一遍，所以存储带宽决定上限。stories15M 读 15.4 MB，在 14 GB/s 的 DDR4 上上限约 900 token/s
2. **并行度要和带宽匹配**：32 路矩阵单元在 250 MHz 下每秒能吃 8 GB 权重。DDR3 32 位的板子 32 路就够；DDR4 64 位要 64 路；HBM 要上千路。多出的乘法器只会闲着等数据
3. **能跑多大的模型由片外容量决定**：1 GB DDR 的板子放不下 1B 模型（int8 约 1.27 GB）
4. **预填充需要 GEMM**：只有 MVM 时，128 token 的提示词要逐个 token 算（stories15M 在 KU040 上 261 ms）；加一个 1024 MAC/周期的 GEMM 阵列后，权重读一次供所有 token 复用，降到 10 ms
5. 当前 RTL 的向量单元每周期 1 元素，占每 token 约 12% 的时间（注意力每行 4 拍）；做成多路可以降到 5% 左右
6. 表中频率是板卡的假设值（如 KU040 按 250 MHz）；当前 RTL 的粗略时序估算约 115 MHz（7 系列），要达到这些速度还需继续优化时序
