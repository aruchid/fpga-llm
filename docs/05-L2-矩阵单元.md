# L2 MVM 计算核

FPGA 大模型推理项目的第三层：用 SystemVerilog 写的矩阵 × 向量计算核，带 AXI 接口，在 Verilator + cocotb 中仿真，输出与 [L0 定点参考模型](03-L0-定点参考模型.md) 逐比特一致。

代码在 `rtl/` 和 `l2/`，总体设计见 [FPGA 矩阵运算通讯全流程](01-总体设计.md)。

## 结构

```
电脑（cocotb 扮演 电脑 + XDMA）
 ├─ AXI4-Lite ──→ 寄存器（KB、NT、SHIFT、启动、状态、周期数）+ x 缓冲
 ├─ AXI-Stream ─→ 权重流（256 位/拍 = 一行 32 个 int8）
 └─ AXI-Stream ←─ 结果流（32 位/拍 = 一个 Q16 结果）
                     │
              mvm_core：32 路 int8 乘加 + 加法树 → 32 个 int32 累加器
                        → ×SW → 舍入移位 → 饱和 int32
```

- **为什么这样分接口**：XDMA 对 FPGA 逻辑暴露的正是 AXI4-Lite（寄存器 BAR）和 AXI-Stream（H2C / C2H 流通道）。RTL 只认 AXI，仿真时由 cocotbext-axi 扮演这些主从端，上板时换成真 XDMA，RTL 不变
- **权重走流，x 走寄存器**：权重量大、只读一遍，适合流式；x 每次只有几百字节，一个任务里被反复使用，放进片上缓冲
- 以后权重常驻板载 DDR，流的来源从 XDMA 换成"从 DDR 读的 DMA"，计算核不变

## 数据流格式

- 大矩阵 (M, K) 切成 32 行一组的输出 tile，K 方向切成 KB 个 32 列块
- 每个 tile：先 4 拍缩放系数 SW（32 个 uint32），再 KB×32 拍权重（块外层、行内层）
- 每拍把一行 32 个权重和 x 的对应块做点积，加到该行的累加器上
- 一个 tile 的权重送完后，逐行做后处理并输出 32 个结果
- M、K 不是 32 的倍数时补零，补零行的 SW = 0，输出 0 后丢弃

后处理与 L0 完全相同：`sat32((acc × SW + 半个 LSB) >> (24 − s))`，24 − s 可能为负（左移）。

## 验证结果（2026-11-16）

| 测试 | 结果 |
|---|---|
| 随机尺寸（含 1×7、40×50、32×1024 等非整块和最大 K） | 逐比特一致 |
| 移位量边界 s = 0 / 1 / 24 / 25（右移 24 到左移 1） | 逐比特一致 |
| 全 ±127 + 最大 SW，结果超出 int32 | 正确饱和，不回绕 |
| 权重流 30% 断续、结果流 50% 反压 | 结果不变 |
| 回放 stories15M 一个 token 的全部 43 次矩阵乘（含 32000×288 的 wcls） | 全部逐比特一致 |

仿真速度：一个 token 约 53 万周期，Verilator + cocotb 约 9 秒。

## 性能

- 每个 tile 周期 = 4（SW）+ KB×32（累加）+ 32（输出），实测每次任务只多 1 个启动周期
- stories15M 一个 token：530,755 周期，其中 wcls（32000×288）占 32.4 万、约 61%
- 假设 250 MHz：约 2.1 ms/token，约 470 token/s（只算计算核，不含非线性运算和 PCIe）
- 此时权重流需要 256 位 × 250 MHz = 8 GB/s，这正是板载 DDR 要提供的带宽
- K=288 时有效计算占 288/324 ≈ 89%。浪费来自输出阶段，可以用两组累加器交替（一组输出时另一组接着算）消掉

## 整模型推理：电脑端调度器

- **模型流程只写一份**：L0 的硬件等价模型改成生成器，每遇到权重矩阵乘就交出一个"请求"。L0 自己直接算；L2 调度器把请求送给 RTL 算，再把结果交回去。这样 L0 和 L2 不可能因为两份代码不同步而出错
- **合并共享输入的矩阵**：q/k/v 三个矩阵输入相同，拼成一个 864×288 的大矩阵一次算完；w1/w3 同理。每行结果互不影响，所以不改变任何一位。每 token 的 RTL 任务从 43 次降到 25 次，写 x 的次数也随之减少
- **权重预打包**：启动时把全部权重打包成流格式（共 15.39 MB），相当于上板时预先加载到 DDR
- 非线性运算（RMSNorm、RoPE、注意力、SiLU）目前仍在电脑端用 L0 定点代码算，不占仿真时间

### 结果（stories15M，2026-11-16）

提示词 "Once upon a time"，贪心生成 32 步，全部矩阵乘由 RTL 完成：

> Once upon a time, there was a little girl named Lily. She loved to play outside in the sunshine. One day, she saw a big

- 32 步的 logits 与 L0 硬件等价模型**逐比特相同**
- 每 token：25 次 RTL 任务，计算核 530,737 周期；仿真时间 2,155 µs（按 250 MHz）
- 每 token 传输：权重流 15.39 MB（约 7.1 GB/s），结果 199 KB，AXI-Lite 写 2620 次、读 50 次
- 仿真速度约 8.5 s/token

### 暴露出的问题：寄存器访问开销

仿真里 AXI-Lite 每次读写只要几个周期，所以 2620 次写只占约 1.5% 的时间。但真实 PCIe 上，每次寄存器写约 0.1~0.5 µs，每次读（要等返回）约 1 µs，加起来是毫秒级，和计算时间（2.1 ms）同一个量级。改进方向：

- x 也改走数据流（或由 DMA 从内存搬），不再一个字一个字写寄存器
- 用中断或描述符队列代替轮询 STATUS
- 最终把非线性运算也搬进 FPGA，整层甚至整个 token 只需电脑发一条命令

这正是 L1 性能模型要量化的内容。

## 已知简化（综合前要处理）

- 32 路乘法 + 加法树、64 位乘法 + 移位都是单周期组合逻辑，综合时要插流水线才能跑到 250 MHz
- x 缓冲用寄存器数组实现，上板应改成 BRAM
- 只实现了 MVM（decode 用）；prefill 的 GEMM 还要做
