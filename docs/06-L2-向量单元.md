# L2 向量单元

FPGA 上执行模型里除权重矩阵乘以外全部运算的 RTL 单元。每个单元与 [L0 定点参考模型](03-L0-定点参考模型.md) 的定点函数逐比特一致。加上 [L2 MVM 计算核](05-L2-矩阵单元.md) 后，stories15M 的全部运算都能在 RTL 仿真中执行。

代码：`rtl/vpu_pkg.sv`、`vpu_units.sv`、`npu_top.sv`，驱动 `l2/vpu_driver.py`，测试 `l2/tb_vpu.py`。算法原理见 [FPGA 上的非线性算子](02-非线性算子原理.md)。

## 模型变成"运算流"

L0 的硬件等价模型改成生成器：每一步运算都交出一个 `Op`，种类只有 7 种：

| 运算 | 作用 | 执行单元 |
|---|---|---|
| matmul | 权重矩阵乘（q/k/v、wo、w1/w3、w2、wcls） | 矩阵单元 mvm_top |
| quant | Q16 向量 → int8 + 移位量 | vpu_quant |
| rmsnorm | RMSNorm | vpu_rmsnorm |
| rope | 旋转位置编码 | vpu_rope |
| attn | 一个注意力头：q·K → 缩放 → Softmax → P·V | attn_head |
| silu_gate | SwiGLU 门控 silu(h1)·h3 | vpu_ew |
| resadd | 残差相加 | vpu_ew |

这个运算流就是将来片上调度器要执行的"指令流"。L0 和 RTL 执行同一份运算流，所以两边不可能因为代码不同步而出错。词嵌入查表和最后的 argmax 留在电脑端。

## 实现要点

- 接口统一为 AXI-Stream，元素 64 位，向量以 tlast 结尾，每周期 1 个元素
- 需要整条向量才能算的运算（quant 的最大值、RMSNorm 的平方和、Softmax 的最大值和总和）先把向量存进单元内缓冲，再输出第二遍
- 查找表（1/√x、1/x、2^x、sigmoid）由脚本从 L0 的表直接生成 `rtl/vpu_luts.svh`，保证两边用同一份数据
- 1/√x、1/x（查表 + 2 次牛顿迭代）按多周期路径处理，等 8 个周期
- 为了与 Python 任意精度整数逐比特一致，内部统一用 128 位运算。这是仿真上的方便做法，综合前要按实测位宽裁剪
- 注意力头一次处理一行（64 个 int8 并行点积）：q 行 → T 个 K 行 → 指数 → 概率 → T 个 V 行 → 输出

## 资源估算

矩阵单元用 yosys 实际综合，7 系列约 2,450 LUT + 256 LUTRAM、2,200 FF、36 DSP（含 AXI 和 x 缓冲），只占 Artix-7 200T 的约 2% LUT、5% DSP。

向量单元按实测位宽裁剪后粗估（**未综合**）：

| 单元 | 主要资源 |
|---|---|
| quant / rmsnorm / softmax 缓冲 | 每个约 2~3 个 BRAM36（2048 × 40 位） |
| rmsnorm、softmax、silu、rope 的乘法 | 合计约 20~30 DSP |
| 查找表 | 共约 1,200 项 × 17 位，用 LUTRAM 或 1 个 BRAM |
| attn_head | 64 路 int8 点积 + 64 路 P·V，约 64~128 DSP；64 个约 56 位累加器 |
| 合计 | 约 100~150 DSP、1~2 万 LUT、10~20 个 BRAM36 |

结论：整个模型的计算单元在 Artix-7 200T 这一级的 FPGA 上就放得下，资源不是问题，**瓶颈是存储带宽**。
