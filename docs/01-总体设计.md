# FPGA 矩阵运算通讯全流程

用 FPGA 模拟"电脑把矩阵发给 FPGA，FPGA 算完 32×32 GEMM / MVM，再把结果传回电脑"的完整链路，先在 Mac 上全流程仿真，再上真实板卡。

## 目标与范围

- 运算：32×32 **GEMM**（矩阵 × 矩阵）和 32×32 **MVM**（矩阵 × 向量）
- 重点：不只是计算核，而是**电脑 → 接口 → FPGA → 计算 → 回传 → 电脑校验**的全流程
- 策略：先仿真跑通、验证正确，再考虑资源、时序和上板

## 整体链路

```
电脑 (Python)
  │  打包：命令 + 尺寸 + 数据 + 校验
  ▼
通讯接口（先用 UART，以后可换）
  ▼
FPGA
  ├─ 接口收发模块（UART RX/TX）
  ├─ 帧解析状态机：识别命令、检查校验、写 RAM
  ├─ BRAM 缓冲：A、B（或向量 x）、结果 C
  ├─ 计算核：MVM / GEMM
  └─ 结果打包 → 接口发回
  ▼
电脑：和 numpy 结果逐个比对
```

### 电脑端（Python）
- **驱动层**：把矩阵打包成数据帧，发送并接收结果
- **后端可切换**：
  - 仿真模式：连接仿真器（cocotb）
  - 上板模式：连接串口或 PCIe 等真实接口
- 上层代码在两种模式下完全一样，换后端即可从仿真切到真板

### FPGA 端（RTL）
1. 通讯接口：UART / PCIe / 以太网等
2. 帧解析状态机：识别命令，检查校验，把数据写进 RAM
3. BRAM 缓冲区：存矩阵 A、矩阵 B 或向量 x、结果 C
4. 计算核：MVM 和 GEMM
5. 结果打包后从接口发回电脑

## 通讯协议草案

| 字段 | 说明 |
|---|---|
| 帧头 | 固定魔数，用于同步 |
| 命令 | 写 A / 写 B / 写 x / 启动 MVM / 启动 GEMM / 读结果 |
| 尺寸 | 行数、列数（本项目固定 32） |
| 数据 | 定点数，按行优先排列 |
| 校验 | CRC 或简单求和 |

数据量（int8 输入、int32 结果）：GEMM 输入 2 KB、输出 4 KB；MVM 输入约 1 KB、输出 128 B。用 UART 传输完全够用。

## 接口选型

| 接口 | 难度 | 速度 | 说明 |
|---|---|---|---|
| **UART 串口** | 低 | 慢（约 0.1~1 MB/s） | 入门首选，几乎所有板子都有，仿真也简单 |
| **Zynq（ARM + FPGA）** | 中 | 快 | 数据先经网络或串口到 ARM，再经 AXI 到 FPGA，要写 ARM 端程序 |
| **PCIe（XDMA）** | 高 | 很快 | 需要 PCIe 板卡，驱动和仿真都复杂 |
| **以太网 UDP** | 中高 | 快 | 需要以太网 MAC 和协议栈 |

结论：单个矩阵的演示用 UART 就够；**目标升级为整模型推理后，改用 PCIe**（见下一节）。

## 升级目标：整个大模型推理（PCIe）

### 权重放在哪是关键
- **Prefill**（处理提示词）以 GEMM 为主；**Decode**（逐 token 生成）以 MVM 为主，每生成一个 token 都要把全部权重读一遍
- 权重每次经 PCIe 传：每 token 要传整个模型（1B int8 ≈ 1 GB），Gen3 x8 实际约 6 GB/s，约 0.17 s/token，PCIe 成为瓶颈
- **权重预先加载到板载 DDR（推荐）**：PCIe 只负责一次性加载权重和传激活值、命令（每 token 几 KB），decode 速度由 **DDR 带宽**决定
- 因此板子必须**同时有 PCIe 和 DDR**，BRAM 装不下模型

### 32×32 计算核如何服务整个模型
- 所有大矩阵乘法切成 32×32 块，由同一个计算核反复执行
- 第一阶段 FPGA 只做矩阵乘法；Softmax、LayerNorm、RoPE 先在电脑上算。代价是每层多次 PCIe 往返，每次延迟几微秒，会累积。以后逐步搬进 FPGA，做法见 [FPGA 上的非线性算子](02-非线性算子原理.md)

### PCIe 的仿真方法
- PCIe 物理层和 XDMA IP 的完整仿真很重，且只能在 Vivado 里跑
- XDMA 对 FPGA 逻辑暴露的是 **AXI 接口**（AXI4 内存映射 / AXI-Stream）
- FPGA 设计只面向 AXI 写：仿真时用 cocotbext-axi 扮演"电脑 + PCIe"，上板时接真 XDMA，RTL 不变
- PCIe、DDR 的带宽和延迟在仿真中用参数建模，估算每 token 耗时

### 分层仿真路线
1. **L0 Python 参考模型**：选小模型，如 llama2.c 的 stories15M（约 1500 万参数），int8 量化后用 numpy 实现完整推理，作为标准答案
2. **L1 性能模型**：用 Python 估算 PCIe、DDR 带宽和计算周期，预测每 token 耗时，辅助选板
3. **L2 RTL 仿真**：计算核 + AXI 接口，用 Verilator + cocotb；电脑端按 L0 流程调度，把矩阵乘法交给 RTL，逐层和 L0 比对
4. **L3 上板**：接 XDMA + DDR

规模粗算：stories15M 每 token 约 1500 万次乘加，按 32 路并行约 50 万周期，Verilator 几秒可跑完，整模型可在 RTL 仿真中运行；1B 规模只能上板。

## 计算核规模

| 运算 | 乘加次数 | 典型结构 |
|---|---|---|
| MVM（32×32 × 32） | 1,024 | 32 个并行乘加单元，约 32 个周期算完 |
| GEMM（32×32 × 32×32） | 32,768 | 脉动阵列（Systolic Array）。全展开 32×32 需要 1024 个 DSP，小板子放不下，通常用 8×8 或 16×16 分块计算 |

脉动阵列也是 TPU 等 AI 加速器的核心结构，和大模型推理里的矩阵乘法直接相关。

## 仿真闭环（Mac 本地，不需要 Vivado）

- **仿真器**：Verilator 或 Icarus Verilog（`brew install verilator icarus-verilog`）
- **测试框架**：cocotb，用 Python 写测试
- **做法**：cocotb 模拟 UART 线路波形，把整个 FPGA 设计当黑盒；Python 发矩阵、收结果，和 numpy 比对
- **可统计**：通讯、计算、回传各占多少时钟周期
- **AI 辅助**：Claude 写 RTL → 跑仿真 → 对比结果 → 修改，全部在本地闭环，每次几秒

## 上板与实现阶段（可选）

- 需要资源占用、时序、频率数据，或要在真板子上跑时，用 Windows 上的 Vivado
- Claude 通过 SSH 执行批处理：`vivado -mode batch -source build.tcl`，读综合和实现报告，不需要 MCP
- 上板后通过串口或 ILA 回传结果，和 numpy 比对

## 建议的开发顺序（整模型推理版）

1. L0：numpy 实现 stories15M 的 int8 推理，输出作为标准答案（已完成，见 [L0 定点参考模型](03-L0-定点参考模型.md)）
2. L1：性能模型，估算 PCIe / DDR / 计算各占多少时间（已完成，见 [L1 性能模型](04-L1-性能模型.md)）
3. MVM 计算核 + AXI 接口，用 cocotbext-axi 仿真（已完成，见 [L2 MVM 计算核](05-L2-矩阵单元.md)）
4. 电脑端调度器：把模型的矩阵乘法切成 32×32 块交给 RTL，逐层比对（已完成，整模型在 RTL 仿真中生成文本，见 [L2 MVM 计算核](05-L2-矩阵单元.md)）
5. 非线性运算 RTL（向量单元），整模型全部运算上 RTL（已完成，见 [L2 向量单元](06-L2-向量单元.md)）
6. GEMM 计算核（分块脉动阵列），用于 prefill
7. 位宽裁剪 + 流水线，RTL 可综合（已完成，粗略时序约 115 MHz，见 [RTL 可综合与时序](07-RTL-可综合与时序.md)）；片上调度器、Vivado 真实时序待做
8. 上板：接 XDMA + DDR
