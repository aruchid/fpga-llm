# RTL 可综合与时序

把 [L2 MVM 计算核](05-L2-矩阵单元.md) 和 [L2 向量单元](06-L2-向量单元.md) 从"只能仿真"改成"能综合、时序上可行"：限定位宽、改用块 RAM、插流水线。改完的每一步都重跑测试，结果始终与 [L0 定点参考模型](03-L0-定点参考模型.md) 逐比特一致。

代码在 `rtl/`，综合结果和时序估算脚本在 `synth/`。

## 为什么要改

第一版 RTL 为了先把正确性做出来，用了几种只适合仿真的写法：

| 写法 | 问题 |
|---|---|
| 内部统一 128 位运算 | 综合出来是 128 位乘法器和加法器，资源和延迟都离谱 |
| 查找表写成数组常量 | yosys 不支持，Vivado 也不一定推成 ROM |
| 1/√x、1/x 的牛顿迭代整个是一大块组合逻辑 | 一拍算完，路径极长 |
| 缓冲区组合读 | 推不出块 RAM，只能用寄存器 |
| 乘法、舍入、变量移位、饱和挤在一拍 | 组合路径长，频率低 |

## 做了什么

### 1. 查找表改成 ROM 函数

`l2/gen_luts.py` 从 L0 的表直接生成 `rtl/vpu_common.svh`，每张表是一个 `case` 函数。Verilator、yosys、Vivado 都能把它综合成 ROM，而且两边用的是同一份数据。

### 2. 按数值范围定位宽

位宽不再"按最宽的来"，而是按模型实际出现的数值范围定，这些范围作为 RTL 的**输入约定**写在源码开头：

| 单元 | 输入约定 |
|---|---|
| quant | \|x\| < 2^39（RoPE 后最大约 2^33） |
| rmsnorm、silu_gate、resadd、rope | 输入为 int32（来自饱和后的矩阵乘或残差） |
| softmax、注意力分数 | < 2^62；注意力移位量 qs + ks ≤ 56 |

在约定范围内与 Python 任意精度整数逐比特一致；测试覆盖了这些范围的边界。

另一个技巧：Softmax 的指数里，x − max < −2^20 时结果必为 0，先截到 −2^20 不改变结果，让后面的乘法从 65 位降到 21 位。

### 3. 通用乘法流水线 mul_pipe

任意位宽的有符号乘法拆成若干 ≤25×18 的部分积（各对应 1 个 DSP48），再逐级两两相加，每级一拍。带有效位和附带信息（tag）一起走，可以接反压。全设计的大乘法都用它。

### 4. 向量单元的统一结构

- 向量缓冲：同步读写的块 RAM
- 数据通路：定长流水线 → 输出 FIFO
- 发射控制：只有"在途数 + FIFO 占用"还有空位才发射下一个元素，所以下游任意反压都不会丢数据；这个判断本身也寄存一拍，留 1 个余量
- 1/√x、1/x：改成状态机，每拍做一步（求最高非零字节 → 字节内位宽 → 粗移位 → 细移位 → 查表 → 每次牛顿迭代 2~3 次乘法 → 舍入 → 移位），共用一个乘法流水线
- 注意力头：16 路并行，一行 64 个元素分 4 拍；q·K 和 P·V 都拆成 选通道 → 乘 → 部分和 → 累加 多级

### 5. 矩阵单元

- 乘加流水线 6 级：选数 → 32 路乘 → 4 路和 → 4 路和 → 2 路和 → 累加
- **双组累加器**：一组在输出时另一组继续累加，输出阶段不再挡住输入
- 输出流水线：读累加器 → ×SW（mul_pipe）→ 加半个 LSB → 移位 → 饱和；饱和改成"高位是否全相同"的判断
- 移位相关常数（半个 LSB、移位方向和位数、kb−1、nt−1）在任务启动时一次算好
- x 缓冲改成同步读（块 RAM）

效果：每个 tile 少了 32 拍输出停顿，stories15M 每 token 矩阵乘从 530,737 降到约 48 万周期。

## 时序估算方法

没有 Vivado 时，用 yosys `synth_xilinx` 综合后导出网表，自己写了 `synth/sta_est.py`：按典型 7 系列延迟（LUT 约 0.9 ns、进位链每级 0.15 ns、组合 DSP 3.2 ns、BRAM 输出 2.2 ns）找最长的寄存器到寄存器路径，并标出路径上的源码信号。

**这只是粗估，用来找该切流水线的地方**，偏保守；真实频率要以 Vivado 布局布线后的时序报告为准。

## 迭代结果（7 系列，估算最长路径）

| 单元 | 第一版可综合 | 加流水线后 | 再拆位宽/移位后 |
|---|---|---|---|
| 矩阵单元 mvm_top | 15.3 ns（65 MHz） | 6.8 ns | **6.1 ns（164 MHz）** |
| quant | 17.4 ns | 10.5 ns | **7.0 ns（143 MHz）** |
| rmsnorm | 19.2 ns | 11.4 ns | **7.4 ns（136 MHz）** |
| softmax | 18.4 ns | 9.5 ns | **8.0 ns（125 MHz）** |
| silu_gate / resadd | 28.3 ns | 7.5 ns | **6.5 ns（154 MHz）** |
| rope | 6.3 ns | 5.7 ns | **5.6 ns（180 MHz）** |
| 注意力头 | 49.9 ns（20 MHz） | 10.4 ns | **8.7 ns（115 MHz）** |

目前整体受注意力头里 1/x 单元的归一化移位和 Softmax 的指数插值限制，按此估算约 115 MHz。

## 资源（yosys 综合，7 系列）

| 单元 | LUT | FF | DSP | 块 RAM |
|---|---|---|---|---|
| 矩阵单元（含 AXI、x 缓冲） | 2,515 | 3,088 | 36 | LUTRAM 278 |
| quant | 429 | 379 | 0 | 5 × BRAM18 |
| rmsnorm | 1,323 | 1,506 | 18 | 2 × BRAM36 |
| softmax | 1,274 | 932 | 7 | 4 × BRAM36 + 2 × BRAM18 |
| silu_gate / resadd | 343 | 573 | 8 | 2 × BRAM18 |
| rope | 165 | 197 | 8 | — |
| 注意力头 | 8,738 | 6,516 | 41 | 4 × BRAM36 + 2 × BRAM18 |
| **合计** | **约 14,800** | **约 13,200** | **118** | 10 × BRAM36 + 11 × BRAM18 |

相当于 Artix-7 200T 的约 11% LUT、5% FF、16% DSP。注意力头最大，主要是 64 个 60 位累加器和 16 路 P·V 的移位器。

softmax 单元在模型里没有单独使用（注意力头内含 Softmax），只用于单独测试，可以不放进最终设计。

## 验证

每次修改后都重跑：
- 矩阵单元：随机尺寸、移位边界、饱和、反压、stories15M 一个 token 的 7 次矩阵乘回放
- 向量单元：7 种运算的随机与边界测试
- 小模型整模型生成 8 步

结果全部逐比特一致。第一版可综合 RTL 还跑过 stories15M 生成 32 步，logits 逐比特相同。

## 验证与周期（最终版，2026-11-16）

- 全部 36 个测试通过；stories15M 生成 32 步，全部运算在 RTL 上，每步 logits 与 L0 逐比特相同
- 每个运算的周期（`tb_vpu.cycle_profile` 实测拟合，并与整模型实测逐项对上）：

| 运算 | 周期 |
|---|---|
| 矩阵乘（每次任务） | nt × (5 + kb × 32) + 46 |
| quant | 2n + 17 |
| rmsnorm | 2n + 70 |
| rope | n + 9 |
| silu_gate / resadd | n + 17 |
| 注意力头 | 10T + hs + 67（K、V 每行 4 拍；指数、概率每行 1 拍） |

- stories15M 每 token（32 步平均）：矩阵乘 483,564 + 向量运算 63,201 = **546,765 周期**（第一版 588,624）
- 调试中发现并修掉一个吞吐问题：quant 的输出 FIFO 太浅（8），"发射许可"晚一拍再留余量后，每 7 拍要停 1 拍（1.17 拍/元素）；加深到 16 后恢复到 1 拍/元素
