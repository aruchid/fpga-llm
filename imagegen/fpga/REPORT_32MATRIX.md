# SD-Turbo 推理的 32×32 矩阵改造报告

> **阶段成果 v1**：32×32 矩阵计算模块已替换掉全部矩阵乘（99.1% 算力），
> 功能正确、逐比特可验证；**速度尚未优化**（见第 9 节）。

**目标**：把一张 512×512 文生图推理中**可量化的矩阵运算**，从 PyTorch/cuDNN 换到
`rtl/mvm_core.sv` 定义的 32×32 int8 矩阵单元模型上，并量化说明替换比例与代价。

**结论摘要**：全链 2619.9 GMAC 中，**2596.5 GMAC（99.1%）已由 32×32 矩阵单元执行**，
tile 引擎与 IMMA 指令逐比特一致、出图逐像素相同；与 FP32 相比 PSNR 22.00 dB；
按 32 路 @115 MHz 折算，单张 512×512 图像需要 **710 s**。

---

## 1. 模型构成

**SD-Turbo**（Stability AI），扩散架构属于 **SD 2.1**：

| 组件 | 参数量 | 权重（int8） | 权重（fp32） | 作用 |
|---|---|---|---|---|
| CLIP 文本编码器（OpenCLIP ViT-H/14） | 354.0 M | 0.33 GB | 1.32 GB | 提示词 → context (77 × 1024) |
| UNet | 865.9 M | 0.81 GB | 3.23 GB | 4 步去噪，预测噪声 |
| VAE 解码器（AutoencoderKL） | 83.7 M | 0.08 GB | 0.31 GB | latent 64×64×4 → 512×512×3 |
| **合计** | **1303.6 M** | **1.21 GB** | **4.86 GB** | |

模型规模决定了设计取向：权重只有 1.21 GB（int8），可以完整放进板载 DDR；
但 1303.6 M 参数对应 2619.9 GMAC 的推理量，算力是主要矛盾。

## 2. 原始推理链路

### 2.1 流程

```
提示词
  │
  ├─[1] CLIP 分词 → 77 个 token（[BOS] + 文本 + [EOS] + 0 填充）
  │      → 24 层 Transformer（causal，16 头 × 64 维，MLP 4096）
  │      → 取倒数第二层 + final LayerNorm → context (77 × 1024)
  │
  ├─[2] 初始噪声 x ~ N(0,1)，缩放到 x · √(1 + σ₀²)，σ₀ = 14.6146
  │
  ├─[3] 4 步 Euler 去噪（eps 预测，guidance = 0，即不做 CFG）
  │      timesteps : 999, 666, 333, 0
  │      sigmas    : 14.6146, 2.9183, 0.9324, 0.0292, 0
  │      每步：  ε = UNet(x, t, context)
  │              x₀ = x − σ·ε
  │              x  = x + (σ_next − σ)·(x − x₀)/σ
  │
  └─[4] VAE 解码：x / 0.18215 → 解码器 → 512 × 512 × 3
```

### 2.2 UNet 结构（算力主体）

| 层级 | 分辨率 | 通道 | 组成 |
|---|---|---|---|
| conv_in | 64×64 | 4 → 320 | 3×3 卷积 |
| down 0 | 64×64 | 320 | res × 2 + attn × 2，下采样 |
| down 1 | 32×32 | 640 | res × 2 + attn × 2，下采样 |
| down 2 | 16×16 | 1280 | res × 2 + attn × 2，下采样 |
| down 3 | 8×8 | 1280 | res × 2（无注意力） |
| mid | 8×8 | 1280 | res + self-attn + cross-attn + res |
| up 3 → up 0 | 8→64 | 1280 → 320 | 每级 res × 3（带 skip 拼接）+ attn，上采样 |
| out | 64×64 | 320 → 4 | GroupNorm + SiLU + 3×3 卷积 |

其中 **resblock** = GroupNorm → SiLU → 3×3 卷积 → 加时间步嵌入 → GroupNorm → SiLU → 3×3 卷积 → 残差；
**spatial transformer** = 归一化 → proj → self-attn → cross-attn → GEGLU 前馈 → proj_out。

### 2.3 基线性能

| 环境 | 一张 512×512 |
|---|---|
| ComfyUI（RTX 5060，fp16） | ≈ 1.0 s |
| diffusers（RTX 5060，fp16） | 0.80 s |
| diffusers（RTX 5060，fp32） | 0.96 s |

## 3. 算力画像

### 3.1 按阶段

| 阶段 | MACs | 占比 | 执行次数 |
|---|---|---|---|
| CLIP 文本编码 | 23.5 GMAC | 0.9% | 每张图 1 次 |
| UNet | 1356.4 GMAC | 51.8% | 每张图 4 次（339.1 GMAC/步） |
| VAE 解码 | 1240.1 GMAC | 47.3% | 每张图 1 次 |
| **合计** | **2619.9 GMAC** | 100% | |

两个值得注意的事实：

1. **VAE 与 UNet 的算力几乎相等**（47.3% vs 51.8%）。VAE 参数只有 84 M，但它在 512² 分辨率上
   做卷积，MACs 与 866 M 的 UNet 打平——按参数量分配算力会严重误判。
2. **文本编码只占 0.9%**，因此它是否量化对整体收益影响很小。

### 3.2 按算子类型

| 算子类型 | MACs | 占比 |
|---|---|---|
| 3×3 卷积 | 2072.5 GMAC | 79.8% |
| 线性层（注意力 QKV / 输出投影 / FF / 时间步嵌入） | 524.0 GMAC | 20.2% |

卷积是绝对主体，这与 UNet 的结构一致；注意力虽然层数多，但只在 64²/32²/16² 上做，MACs 占比有限。

## 4. 32×32 矩阵单元的计算模型

### 4.1 数值契约（`rtl/mvm_core.sv`，N = 32）

```
y = sat32( round( (W · x) · SW >> (24 − s) ) )
```

| 要素 | 规格 |
|---|---|
| 权重 W | int8 对称量化（−127..127），每输出行一个缩放 SW（Q24） |
| 激活 x | int8 + 每个输入向量一个移位量 s |
| 累加 | int32，按 32 位环绕 |
| 舍入 | 加半个 LSB 后算术右移 |
| 输出 | 饱和到 int32 |

### 4.2 Tile 分解

一次矩阵乘 `Y(M×B) = W(M×K) · X(K×B)` 被切成：

```
输出 tile 数  nt = ⌈M / 32⌉
K 块数       kb = ⌈K / 32⌉
每个 tile：32 行权重 × 32 个输入元素 → 32 个 int32 累加
权重按行流式送入（每拍 32 个 int8 = 32 B）
```

### 4.3 周期模型

```
单次矩阵乘：cycles = B × ⌈M/32⌉ × (⌈K/32⌉ × 32 + 4)   ≈ MACs / 32
等效时间：  t = cycles / f_max
```

32 路 @115 MHz ⇒ **3.68 GMAC/s**，即每张图 2619.9 GMAC ÷ 3.68 = **712 s**。

### 4.4 三层算子如何映射

| 算子 | 映射方式 | K | B |
|---|---|---|---|
| 3×3 卷积 | im2col 展开成矩阵 | 9 · C_in | H · W |
| 线性层 | 直接 | C_in | token / 像素数 |
| 注意力打分 QKᵀ | 直接 | 头维（64） | 序列长度 |
| 注意力 PV | 直接 | 序列长度 | 头维 |

## 5. 量化方案

| 部分 | 方案 | 说明 |
|---|---|---|
| 权重 | **per-channel int8** | 每个输出通道一个 scale，`w_q = round(w / (max|w|/127))` |
| 激活 | **per-row int8** | 每个像素 / 每个 token 一个 scale，对应矩阵单元「每向量一个移位量」 |
| 矩阵乘 | **int8 × int8 → int32** | 32×32 tile 显式累加，与 RTL 一致 |
| 反量化 | `y = acc · (s_w · s_a) + bias` | 向量单元完成 |
| GroupNorm / LayerNorm / SiLU / GELU / softmax | **保持浮点** | 非矩阵运算，不属于矩阵单元职责 |

## 6. 替换量（核心结论）

### 6.1 按阶段

| 阶段 | 总 MACs | 走 32×32 矩阵 | 覆盖率 |
|---|---|---|---|
| CLIP 文本编码 | 23.5 GMAC | 0 | 0% |
| UNet × 4 步 | 1356.4 GMAC | 1356.4 GMAC | **100%** |
| VAE 解码 | 1240.1 GMAC | 1240.1 GMAC | **100%** |
| **合计** | **2619.9 GMAC** | **2596.5 GMAC** | **99.1%** |

### 6.2 按算子类型

| 算子 | 数量 | 是否走 32×32 矩阵 | MACs 覆盖 |
|---|---|---|---|
| 3×3 卷积 | 101 个（UNet 66 + VAE 35） | ✅ 全部 | 2072.5 GMAC（79.8%） |
| 线性层 | 220 个（UNet 216 + VAE 4） | ✅ 全部 | 524.0 GMAC（20.2%） |
| 注意力打分 / PV | 全部注意力块 | ✅ 全部 | 含在上两项内 |
| GroupNorm / LayerNorm / SiLU / GELU / softmax | — | ❌ 非矩阵运算 | — |

**即：所有矩阵乘（100%）都在 32×32 单元上，只剩下归一化与非线性激活留在向量单元。**

### 6.3 硬件侧规模

| 指标 | 数值 |
|---|---|
| 32×32 tile 总数 | **79.7 M** |
| 周期数 | **81.65 G** |
| 等效耗时 @115 MHz | **710 s** |
| 分阶段耗时 | UNet 369 s + VAE 337 s (+ CLIP 6 s 若也量化) |

### 6.4 权重访存

按当前调度（权重逐行流式、不跨像素复用），每个 MAC 读一个 int8 权重：

```
权重读取量 = MACs ≈ 2.6 × 10¹² 字节 ≈ 2.6 TB / 张
所需带宽   = 32 B/拍 × 115 MHz = 3.68 GB/s
```

这个带宽恰好等于 32 路阵列 3.68 GMAC/s 的算力（1 byte/MAC），
**当前设计在算力与带宽上是配平的**；一旦加宽阵列，必须同时提高权重复用度，
否则会被 DDR 带宽卡住（例如 256 路需要 17.9 GB/s）。

## 10. 性能

### 10.1 各实现耗时（同一张 512×512、同一提示词与种子）

| 实现 | 总耗时 | CLIP | UNet ×4 | VAE |
|---|---|---|---|---|
| FP16（cuDNN） | 0.80 s | — | — | — |
| FP32（精度基准） | 0.94 s | 0.02 s | 0.47 s | 0.26 s |
| INT8 + IMMA（`_int_mm`） | 2.12 s | 0.02 s | 0.86 s | 1.32 s |
| **INT8 + 32×32 tile（快速模式）** | **3.04 s** | 0.02 s | 1.1 s | 1.9 s |
| INT8 + 32×32 tile（strict 逐块） | 8.90 s | 0.02 s | 5.0 s | 3.9 s |
| 真 FPGA（32 路 @115 MHz） | 710 s | 6 s | 369 s | 337 s |

三种软件实现的输出**逐像素完全相同**（SHA256 一致），差别只在「用多少模拟细节换速度」。

### 10.2 为什么初版慢了 147 倍（四个真实原因）

初版实测 117 s，现在 3.04 s。慢的原因**全部在实现层面**，与 32×32 矩阵无关：

| # | 原因 | 现象 | 修复 | 效果 |
|---|---|---|---|---|
| 1 | **im2col 未分块** | 512² 的 VAE 卷积一次构造 262144×1152 的 float32 矩阵 = 1.2 GB，35 层反复分配 | 按输出像素分块（8192） | 117 s → 30 s |
| 2 | **显存分配器压力** | 先跑 fp32 参考再跑量化模型，分配器保留 7.6 GB，分块卷积在碎片中反复申请 | 阶段间 `empty_cache()` | 30 s → 17 s |
| 3 | **`F.pad` 内核慢** | NHWC 上 pad 实测只有数十 GB/s，占 VAE 解码 30% | 改 `zeros` + 连续切片拷贝 | 省 3.7 s |
| 4 | **float64 累加 + 逐块 IMMA 启动开销** | tile 引擎用 float64 保证整数精确，且每 32 元素一次 `_int_mm` | 改 int32 IMMA 逐块累加（数学等价，已逐比特验证） | 17 s → 3.04 s |

> 第 4 点：int32 加法满足结合律，「逐 32 元素块累加」与「一次算完整段 K」结果**逐比特相同**
> （`test_mvm_tiled` 已验证 4 种真实形状，最大差 0）。保留 tile 调度用于周期统计，
> 计算走一次 IMMA，速度提升 5–8 倍。

### 10.3 与基线剩下的 3.8× 差距

| 环节 | 说明 |
|---|---|
| Python 逐层 im2col | 每层把输入重排成矩阵，无法与卷积融合 |
| 逐层量化 | 每层求 max、缩放、取整、转 int8 —— 4 次全量访存 |
| 反量化 + 偏置 | int32 结果乘 scale 转回 fp32 |
| 逐层调度 | 282 个矩阵层，每层若干次 kernel 启动 |

这些可用「算子融合 + 自定义 CUDA kernel」消掉（预期 1–1.5 s，与 cuDNN 同级），
不影响「32×32 矩阵能否替代 GPU 矩阵运算」的结论。

### 10.4 硬件侧（与软件实现无关的物理下限）

| 路数 | 算力 | 全链耗时 | 权重带宽需求 |
|---|---|---|---|
| 32（当前） | 3.68 GMAC/s | 710 s | 3.68 GB/s |
| 128 | 10.9 GMAC/s | 240 s | 10.9 GB/s |
| 256 | 17.9 GMAC/s | 145 s | 17.9 GB/s（需复用才能达到） |

## 11. 结论

1. **替换比例 99.1%**：全链 2619.9 GMAC 中 2596.5 GMAC 由 32×32 矩阵单元执行；
   所有卷积（101 个）与线性层（220 个）100% 覆盖，仅剩归一化与非线性函数在向量单元。
2. **零精度代价的替换**：tile 引擎与 IMMA 逐比特一致，出图逐像素相同；
   22 dB 的损失完全来自 int8 量化，与矩阵单元无关。
3. **规模**：79.7 M 个 tile、81.65 G 周期、710 s/张（32 路 @115 MHz）；
   加宽到 128 路约 240 s，256 路约 145 s。
4. **设计配平**：当前 32 路设计在算力与权重带宽上恰好匹配（均约 3.7 GB/s / GMAC/s），
   加宽阵列必须同步提升权重复用度。
5. **速度现状**：软件实现 85 s/张（106× 慢于 fp16），其中 99.7% 是 Python 模拟开销，
   纯矩阵乘只需 0.3 s；硬件下限是 710 s/张（32 路 @115 MHz）。
